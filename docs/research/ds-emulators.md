# DS emulators: can they display the FFTA2 widescreen mod?

Researched 2026-11-23 from primary sources: source code at a pinned tag or commit, official docs, release notes and store listings. Each claim links to its source. Secondary sources are marked **(secondary)**. No emulator was run for this. Every verdict comes from reading settings and code.

## What an emulator has to do

1. **Raised 3D internal resolution.** It must render 3D above 256x192.
2. **Bottom screen only.** It must be able to show the bottom DS screen and nothing else.
3. **Unlocked stretch.** It must stretch that screen to a non-4:3 shape. Integer scaling only, or a locked 4:3, does not count.
4. **SELECT on a controller or touch button.** The mod uses a tap of SELECT and a ~0.5 s hold of SELECT as two separate controls. Any hotkey that also uses SELECT is a conflict.

Baseline that was already confirmed: melonDS 1.1 (Flathub, Linux) with OpenGL, 8x–9x internal resolution, Screen sizing "Bottom only", bottom aspect "Window" and no filtering.

**A note on requirement 3.** There are two ways to meet it:
- **Fill the window** (melonDS "window", RetroArch "Full"). This gives the right shape only when the window or display has the shape the mod was squeezed from.
- **A fixed 16:9 preset** (melonDS "Bottom 16:9", RetroArch "16:9", NooDS "16:9", melonDS Android "16:9 (Widescreen)"). This gives 16:9 on any display, with black bars where the display differs.

The confirmed 384x216 view on 1920x1080 is 16:9. The Steam Deck's own screen is 1280x800, which is 16:10 ([Steam Deck tech specs](https://www.steamdeck.com/en/tech)). On the Deck, "fill the window" would therefore stretch a 16:9 view to 16:10.

## Per-emulator notes

### melonDS 1.1 (desktop)
- **Version and platforms.** 1.1 was released 2025-11-18 ([release](https://github.com/melonDS-emu/melonDS/releases/tag/1.1)). Builds exist for Windows x64/ARM64, macOS Universal, Linux x64/ARM64 and the BSDs ([downloads](https://melonds.kuribo64.net/downloads.php)). It is also on [Flathub](https://flathub.org/apps/net.kuribo64.melonDS).
- **Renderers.** The video dialog offers Software, OpenGL (Classic) and OpenGL (Compute shader). The compute button is disabled under `__APPLE__` ([VideoSettingsDialog.cpp L71-L87](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/VideoSettingsDialog.cpp#L71-L87)). The OpenGL renderers are built by default on every OS ([CMakeLists.txt L68](https://github.com/melonDS-emu/melonDS/blob/1.1/CMakeLists.txt#L68), [src/CMakeLists.txt L89-L101](https://github.com/melonDS-emu/melonDS/blob/1.1/src/CMakeLists.txt#L89-L101)). So macOS gets OpenGL Classic but not compute.
- **Resolution and 2D.** Internal resolution runs 1x–16x ([VideoSettingsDialog.cpp L96-L98](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/VideoSettingsDialog.cpp#L96-L98), [Config.cpp L82](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Config.cpp#L82)). The FAQ says the setting "only changes the internal resolution for 3D graphics" ([FAQ](https://melonds.kuribo64.net/faq.php)). The OpenGL compositor uploads the 2D layers at native 256x192 ([GPU_OpenGL.cpp L263-L265](https://github.com/melonDS-emu/melonDS/blob/1.1/src/GPU_OpenGL.cpp#L263-L265)).
- **Compute renderer.** 1.1 added "tile size scaling to alleviate glitches at high resolutions" ([release](https://github.com/melonDS-emu/melonDS/releases/tag/1.1)).
- **Screen menus.** The Screen sizing list includes "Top only" and "Bottom only", followed by "Force integer scaling" ([Window.cpp L546-L566](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Window.cpp#L546-L566)). Aspect ratio has separate Top and Bottom groups ([Window.cpp L569-L597](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Window.cpp#L569-L597)) with the values 4:3, 5:3, 16:9, 21:9 and "window" ([Screen.h L42-L49](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Screen.h#L42-L49)).
- **Input.** Config > Input and hotkeys ([Window.cpp L628](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Window.cpp#L628)) has a Select mapping ([InputConfigDialog.ui L673](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/InputConfig/InputConfigDialog.ui#L673)). Every joystick mapping defaults to -1, meaning unbound ([Config.cpp L51-L52](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Config.cpp#L51-L52)). One mapping can hold a button and an axis, and *either* one triggers it ([EmuInstanceInput.cpp L359-L411](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/EmuInstanceInput.cpp#L359-L411)). There is no modifier or chord concept.

### melonDS on Steam Deck and EmuDeck
- **Desktop Mode.** The Flathub app is the same 1.1 Linux build, so everything above applies, compute renderer included.
- **EmuDeck's melonDS config.** EmuDeck installs the `net.kuribo64.melonDS` Flatpak ([emuDeckMelonDS.sh L4-L8](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/functions/EmuScripts/emuDeckMelonDS.sh#L4-L8)) and copies its own `melonDS.toml`. That file sets `Renderer = 1` (OpenGL Classic) and `ScaleFactor = 3` ([melonDS.toml L146-L151](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/net.kuribo64.melonDS/config/melonDS/melonDS.toml#L146-L151)). It also sets `ScreenLayout = 3` (Hybrid), `ScreenSizing = 3` (Auto) and `ScreenAspectTop/Bot = 4`, where id 4 is "5:3 (3DS)" ([melonDS.toml L96-L109](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/net.kuribo64.melonDS/config/melonDS/melonDS.toml#L96-L109); id meaning from [Screen.h L42-L49](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/Screen.h#L42-L49)). Its resolution presets rewrite ScaleFactor to 4/6/8/11 ([emuDeckMelonDS.sh L177-L199](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/functions/EmuScripts/emuDeckMelonDS.sh#L177-L199)). EmuDeck's wiki confirms the hybrid default ([EmuDeck wiki: melonDS](https://emudeck.github.io/emulators/steamos/melonds/)).
- **SELECT conflict inside melonDS.** In `[Instance0.Joystick]`, EmuDeck sets `Select = 6` and `HK_FastForward = 86048774` ([melonDS.toml L21-L55](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/net.kuribo64.melonDS/config/melonDS/melonDS.toml#L21-L55)). melonDS decodes a mapping as button = `val & 0xFFFF`, an axis flag at bit 16, axis number = `(val>>24)&0xF` and direction = `(val>>20)&0xF` ([EmuInstanceInput.cpp L359-L411](https://github.com/melonDS-emu/melonDS/blob/1.1/src/frontend/qt_sdl/EmuInstanceInput.cpp#L359-L411)). So 86048774 = 0x05210006 means **button 6 or axis 5 as a trigger**. Button 6 is the same button EmuDeck uses for DS Select.
- **What that does to the mod.** Every SELECT press would also hold fast-forward, and EmuDeck's config sets `FastForwardFPS = 1000.0` ([melonDS.toml L5](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/net.kuribo64.melonDS/config/melonDS/melonDS.toml#L5)). If the mod counts the ~0.5 s hold in game frames, a short tap could pass as a hold. That last point is an inference from the config and was not tested.
- **The fix.** Clear the button from Fast Forward in Config > Input and hotkeys.
- **EmuDeck Steam Input template.** The template "EmuDeck - Controller Hotkeys" uses button chords for melonDS standalone ([emudeck_controller_steamdeck.vdf L5-L6](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/steam-input/emudeck_controller_steamdeck.vdf#L5-L6)). The View button still sends xinput SELECT ([L770-L778](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/steam-input/emudeck_controller_steamdeck.vdf#L770-L778)). Chords on `chord_button 15` (labelled Select) send keyboard keys, for example Select+A = Pause ([L240-L251](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/steam-input/emudeck_controller_steamdeck.vdf#L240-L251)).
  - The wiki lists these Select combos for melonDS: Select+R3 full screen, Select+R1 save state, Select+L1 load state, Select+R2 fast forward, Select+A pause, Select+L3 reset, Select+Start stop, Select+Y swap screens ([EmuDeck wiki: melonDS](https://emudeck.github.io/emulators/steamos/melonds/)).
  - The template file adds Select+B screenshot, Select+L2 rewind and Select+X swap ([vdf L267-L334, L464-L516](https://github.com/dragoonDorise/EmuDeck/blob/52258a6544835433c30ff036bfe34cf33e74a6a7/configs/steam-input/emudeck_controller_steamdeck.vdf#L267-L334)).
  - The wiki puts lid and FPS limit on Start+DPad, but the file's labels say "Select + DPad Up/Right" on `chord_button 14`. The labels and the chord button disagree.
  - Effect on the mod: a bare SELECT tap or hold still passes through as SELECT. Pressing another face or shoulder button while holding SELECT fires an EmuDeck hotkey.

### RetroArch (all platforms)
- **Version.** Latest release is 1.22.2, from 2025-11-20 ([release](https://github.com/libretro/RetroArch/releases/tag/v1.22.2)).
- **Aspect ratio.** The list includes 4:3, 16:9, 16:10, Core Provided, Custom and "Full" ([video_driver.c L176-L202](https://github.com/libretro/RetroArch/blob/v1.22.2/gfx/video_driver.c#L176-L202), [msg_hash_us.h L2609](https://github.com/libretro/RetroArch/blob/v1.22.2/intl/msg_hash_us.h#L2609)). "Full" uses the viewport's width and height ([video_driver.c](https://github.com/libretro/RetroArch/blob/v1.22.2/gfx/video_driver.c)). The menu path is Settings > Video > Scaling > Aspect Ratio ([libretro docs, FBNeo page](https://docs.libretro.com/library/fbneo/)). "Integer Scale" sits in the same section and defaults to off ([config.def.h L530](https://github.com/libretro/RetroArch/blob/v1.22.2/config.def.h#L530)).
- **Hotkey Enable defaults.** It is unbound by default ([config.def.keybinds.h L282-L283](https://github.com/libretro/RetroArch/blob/v1.22.2/config.def.keybinds.h#L282-L283)). The menu-toggle gamepad combo defaults to none on desktop, Android and iOS, and to Start+Select only on some consoles ([config.def.h L928-L940](https://github.com/libretro/RetroArch/blob/v1.22.2/config.def.h#L928-L940)).
- **Why Hotkey Enable on Select breaks the mod.** Once Hotkey Enable has been held past `input_hotkey_block_delay` frames, RetroArch sets `INP_FLAG_BLOCK_LIBRETRO_INPUT` and the core gets no input from that port ([input_driver.c L5675-L5697](https://github.com/libretro/RetroArch/blob/v1.22.2/input/input_driver.c#L5675-L5697)). The delay defaults to 5 ([config.def.h L1655](https://github.com/libretro/RetroArch/blob/v1.22.2/config.def.h#L1655)). The setting's own help text says the delay exists so that the key's normal input "(e.g. RetroPad 'Select')" can still be captured ([msg_hash_us.h L3819-L3825](https://github.com/libretro/RetroArch/blob/v1.22.2/intl/msg_hash_us.h#L3819-L3825)). So when Hotkey Enable is on Select, the core sees only about the first 5 frames of a SELECT hold.
- **Touch overlay.** The default overlay (neo-retropad) has a SELECT button ([neo-retropad.cfg L192-L194](https://github.com/libretro/common-overlays/blob/master/gamepads/neo-retropad/neo-retropad.cfg#L192-L194)).
- **Core availability.** The libretro buildbot carries DeSmuME, melonDS DS, legacy melonDS and NooDS cores for Windows, Linux, macOS, Android and iOS ([buildbot ios-arm64](https://buildbot.libretro.com/nightly/apple/ios-arm64/latest/), [android arm64](https://buildbot.libretro.com/nightly/android/latest/arm64-v8a/)).

- **Release.** v1.4.0 integrated the compute renderer "on Windows and Linux builds. Android is not yet supported, and Apple devices likely never will be" ([release](https://github.com/JesseTG/melonds-ds/releases/tag/v1.4.0)). The README says compute needs OpenGL 4.3, which macOS lacks ([README L235-L249](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/README.md#L235-L249)). v1.3.0 fixed OpenGL on macOS ([release](https://github.com/JesseTG/melonds-ds/releases/tag/v1.3.0)).
- **No OpenGL on Android or iOS.** OpenGL is disabled by default when `ANDROID OR IOS` ([CMakeLists.txt L63-L68](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/CMakeLists.txt#L63-L68)). Any non-desktop GL profile is a fatal configure error ("melonDS does not support OpenGL ES yet", [L80-L82](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/CMakeLists.txt#L80-L82)). The libretro CI does not override this for Android or iOS ([.gitlab-ci.yml L113-L162](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/.gitlab-ci.yml#L113-L162)). Those builds are therefore software-only at 256x192.
- **Video options.** "Render Mode" offers Software / OpenGL (Classic) / OpenGL (Compute) and falls back to software if OpenGL can't be used. "Internal Resolution" runs 1x–8x and is "OpenGL renderers only" ([video.hpp L26-L78](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/src/libretro/config/definitions/video.hpp#L26-L78)).
- **Layout options.** There are "# of Screen Layouts" and "Screen Layout #1…" with "Bottom Only" ([screen.hpp L412-L455](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/src/libretro/config/definitions/screen.hpp#L412-L455)).
- **Steam.** The README says Steam's RetroArch doesn't include the core, but it can be installed manually ([README L24-L31](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/README.md#L24-L31)).
- **Buttons.** Select maps to DS Select. L2 = pointer speed and alternate controls, R2 = touch, L3 = mic, R3 = next layout, L2+Y = close lid ([input.cpp L52-L71](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/src/libretro/input/input.cpp#L52-L71), [joypad.cpp L65-L101](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/src/libretro/input/joypad.cpp#L65-L101)). Select+Up and Select+Down are defined as light-level combos ([joypad.cpp L47-L48](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/src/libretro/input/joypad.cpp#L47-L48)). They are only used when a solar sensor is in Slot-2 ([input.cpp L127](https://github.com/JesseTG/melonds-ds/blob/v1.4.0/src/libretro/input/input.cpp#L127)).

### DeSmuME (libretro)
- **Options.** "Internal Resolution" runs 1x–10x ([libretro_core_options.h L324-L345](https://github.com/libretro/desmume/blob/95b4d798731caa809125b6c3c11d17cc332ff6ef/desmume/src/frontend/libretro/libretro_core_options.h#L324-L345)). "OpenGL Rasterizer" exists only in `HAVE_OPENGL` builds ([L346-L360](https://github.com/libretro/desmume/blob/95b4d798731caa809125b6c3c11d17cc332ff6ef/desmume/src/frontend/libretro/libretro_core_options.h#L346-L360)). - **Software upscaling.** The core starts with the SoftRasterizer and sets the custom framebuffer size from the resolution option ([libretro.cpp L1538-L1540](https://github.com/libretro/desmume/blob/95b4d798731caa809125b6c3c11d17cc332ff6ef/desmume/src/frontend/libretro/libretro.cpp#L1538-L1540)). So upscaling also works on builds without OpenGL. The Android build defines no OpenGL ([jni/Android.mk](https://github.com/libretro/desmume/blob/95b4d798731caa809125b6c3c11d17cc332ff6ef/desmume/src/frontend/libretro/jni/Android.mk)).
- **Buttons and aspect.** The core binds L2 = lid, L3 = mic, R2 = tap stylus, R3 = quick screen switch, and Select = Select ([libretro.cpp L2426-L2432](https://github.com/libretro/desmume/blob/95b4d798731caa809125b6c3c11d17cc332ff6ef/desmume/src/frontend/libretro/libretro.cpp#L2426-L2432)). It reports an aspect of 0, so RetroArch derives it from the dimensions ([libretro.cpp L704](https://github.com/libretro/desmume/blob/95b4d798731caa809125b6c3c11d17cc332ff6ef/desmume/src/frontend/libretro/libretro.cpp#L704)).
- **Steam.** It is on Steam as the free "RetroArch - DesmuME" DLC ([Steam](https://store.steampowered.com/app/1227467/RetroArch__DesmuME)). Among RetroArch's 65 Steam DLCs, it is the only DS core ([Steam appdetails API](https://store.steampowered.com/api/appdetails?appids=1118310)).

## Open questions

1. **DraStic layouts.** Can a custom layout hide the top screen and stretch the bottom one freely? No first-party docs survive. The developer site is parked and the Play listing has been removed.
2. **Steam Deck Desktop Mode input.** How do the Deck's built-in controls reach melonDS (Flathub) when it is launched outside Steam? Do they arrive as a gamepad SELECT, and does Steam's Desktop controller layout interfere? Not covered by any primary source checked.
3. **EmuDeck's Fast Forward binding.** Is `HK_FastForward` on button 6 intentional? It may be an encoding artefact from EmuDeck's editor. In-emulator testing would confirm whether pressing View fast-forwards with the shipped config.
4. **Steam Input chords.** When the View button is a chord modifier in EmuDeck's template, does Steam also send the plain SELECT press immediately, or only on release? The template binds both, but the timing is not documented.
5. **RetroArch video driver.** Does melonDS DS get its OpenGL context with RetroArch's default video driver on each platform (Vulkan is common on Linux and Windows)? Or must the driver be set to `gl`/`glcore`? The core only says it falls back to software.
6. **DeSmuME on phones.** How fast does libretro DeSmuME's software rasterizer run at 3x–4x on phones? Speed was not assessed.
7. **DeSmuME in App Store RetroArch.** Does the App Store build of RetroArch iOS bundle the DeSmuME core? The buildbot has an iOS build, but the App Store notes don't list it.
8. **Manic EMU.** What layout and aspect options does its DS core offer?
9. **NooDS 2x.** Is 2x good enough for the mod, given that the baseline uses 8x–9x? That is a visual judgement, not a source question.
10. **Stretch target vs. squeeze aspect.** For every "fill the window" option, the window or display must have the same aspect the mod squeezes from. A fixed 16:9 preset is safer on 16:10 (Steam Deck) and ~20:9 (phone) screens.
